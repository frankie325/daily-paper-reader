# Abstract 

Multimodal large language models (MLLMs) have demon-strated strong language understanding and generation ca-pabilities, excelling in visual tasks like referring and grounding. However, due to task type limitations and dataset scarcity, existing MLLMs only ground objects present in images and cannot reject non-existent objects ef-fectively, resulting in unreliable predictions. In this paper, we introduce ROD-MLLM , a novel MLLM for Reliable 

Object Detection using free-form language. We propose a query-based localization mechanism to extract low-level object features. By aligning global and object-level visual information with text space, we leverage the large language model (LLM) for high-level comprehension and final lo-calization decisions, overcoming the language understand-ing limitations of normal detectors. To enhance language-based object detection, we design an automated data an-notation pipeline and construct the dataset ROD . This pipeline uses the referring capabilities of existing MLLMs and chain-of-thought techniques to generate diverse expres-sions corresponding to zero or multiple objects, addressing the shortage of training data. Experiments across various tasks, including referring, grounding, and language-based object detection, show that ROD-MLLM achieves state-of-the-art performance among MLLMs. Notably, in language-based object detection, our model achieves +13.7 AP im-provement on D 3 benchmark over existing MLLMs and sur-passes most specialized detection models, especially in sce-narios requiring complex language understanding.

Our main contributions are as follows: • We propose ROD-MLLM , a multimodal large language model that can perform language-based object detection. It achieves unified object localization based on free-form language descriptions and can reject non-existent objects. • We design an automated annotation pipeline for lan-guage based detection, and build ROD dataset containing over 500K object description-image pairs. This dataset can effectively improve the detection ability for free ob-ject description, alleviating the shortcomings of general MLLMs that can only perform REC tasks. • We conduct experiments on various benchmarks related to object localization and generation, including language-based object detection, REC and region captioning. Our results demonstrate superior performance across these tasks compared with other MLLMs. 

# 2. Related Work 

2.1. Language-Based Object Detection 

Language-based object detection expands the fixed cate-gories of traditional closed-set detection [27, 44] to free-form descriptions, making it significantly more challenging. Some vision-language models [14, 26, 32] reformulates this task into a region-phrase matching task. They em-ploy region-level contrastive learning inspired by CLIP [42] and unify grounding and detection datasets. Although these specialized models have made initial progress in language-based object detection, their reliance on normal language models like BERT [12] limits their language comprehen-sion capabilities, making it difficult to handle complex de-scriptions. To evaluate this new challenging task, several manually annotated benchmarks have been proposed, such as OmniLabel [43] and D 3 [50]. They feature rich object ex-pressions designed by humans and include diverse bound-ing box annotations. However, there is currently no dedi-cated dataset available for training to enhance the capabili-ties of models in language-based object detection. To the best of our knowledge, we are the first to pro-pose an automated annotation pipeline for generating train-ing data for language-based object detection, which lever-ages the MLLMs’ capabilities in referring and reasoning to generate descriptions and match them with bounding boxes.

# 3. Method 

In this section, we introduce the architecture of ROD-MLLM as shown in Fig. 2. It consists of two parts: low-level localization and high-level comprehension, which will be explained in Sec. 3.1 and Sec. 3.2. 

3.1. Low-Level Localization 

Query Based Localization. There are three main ways to represent object coordinates in language models: spe-cial coordinate tokens [6, 47], textual coordinate boxes [5, 55, 61], and decoupled coordinate box extraction proposed in Groma [35]. For the precision of detection boxes, we follow the third approach. However, Groma incurs signif-icant training costs to obtain a class-agnostic region pro-posal network (RPN), which limits its generalization to novel objects [37]. Different from this, we propose query based localization mechanism. Specifically, we first sim-plify the language-based detection to open vocabulary de-tection (OVD) for recalling candidate objects, which is suit-able for existing open vocabulary detectors. As shown in the lower part of Fig. 2, we extract the object expression be-tween the special tags <p> and </p> from the user query, and use N-gram to extract mentioned objects, which are then used as text queries for the low-level locator (OVD) to extract candidate boxes B:

B = L(I, Oquery , Ocommon ) (1) where L is the low-level locator, I is the image, Oquery is the set of query objects and Ocommon is the set of common objects from COCO [27] which is used for normal VQA perception enhancement when there are no query objects. This process not only leverages the powerful localization capabilities of the low-level locator but also avoids its short-comings in understanding complex sentence contexts. Ad-ditionally, the query objects extraction mechanism reduces the computational burden of irrelevant candidate boxes in-creasing the length of the visual information context.

# 4. Data Annotation Pipeline 

Currently, most detection datasets [25, 27, 44] are designed for predefined simple categories, while the language-based object detection datasets OmniLabel [43] and D 3 [50] serve only for evaluation. To address data scarcity, we design an automated annotation pipeline. We focus on datasets that already have bounding box annotations, specifically detec-tion (Sec. 4.1) and grounding (Sec. 4.2) datasets. 

4.1. Building Data from Detection Dataset 

Step 1. Object Description Generation. As shown in Fig. 5(left), we use the Objects365 dataset [44] as detec-tion data source. By limiting the number (no more than 10) and the IoU ( < 0.5) of instances, we sample 100K im-ages for categories in Objects365. Since detection datasets only provide simple categories, we expand them into lan-guage descriptions. One useful feature is that while current MLLMs can hardly find all instances based on a description, they excel at the reverse task, which is generating descrip-tions based on given coordinates. So we choose InternVL2-76B [7, 8] to generate descriptions for its strong under-standing of coordinates. For an image-object category-coordinate triplet ⟨I, O, C ⟩, we input it into InternVL2-76B to generate an object description. Ultimately, we obtain a collection of object descriptions Sdesc .

Inspired by vision-language com-positionality [15, 22, 58], we decompose a description into several conditions that must be met to reduce the difficulty of subsequent judgment. As shown in Fig. 5, the description “dolphin swimming near the edge of a pool ” can be decom-posed into three conditions. An object satisfies a description if and only if it meets all the conditions. Through few-shot contextual learning, the LLM DeepSeek [28] can accurately decompose the description into conditions. 

Step 3. COT based Condition Judgment. Using the ob-ject description conditions from the previous step, we an-notate each description for two images: the source image, serving as a positive sample with the object present, and a randomly sampled image of the same category, likely not matching the description, as a negative sample. To improve annotation accuracy, we propose a chain-of-thought (COT) based condition judgment. We input the list of objects and conditions into the MLLM, asking it to assess whether each object meets a specific condition. The MLLM first de-scribes the actual situation of the object in the image as a reason, then provides its judgment on whether the object meets the condition. Then we obtain a set of object descrip-tions along with their matching or non-matching object sets. 

4.2. Building Data from Grounding Dataset 

The annotation of grounding dataset include two steps: 

Step 1. Generating Existing Objects. Flickr30K Enti-ties [41] provides five captions for each image, with co-ordinate box annotations for entities within the captions as shown in Fig. 5(right). Typically, existing methods use this dataset solely for phrase localization tasks, ne-glecting its rich linguistic context. We transform it into a language-based detection dataset focused on single ob-ject description. Specifically, we input the set of cap-tions C = {c1, c 2, . . . , c 5} for each image into the LLM DeepSeek [28] and mark the entities within the captions. We manually design examples to guide the LLM in expand-ing the entities into descriptive phrases, which capturing rich information about the objects’ attributes, states, actions and relationships. For each image, we generate approxi-mately 5 object descriptions of existing objects. 

Step 2. Generating Non-existent Objects. To achieve language-based detection, we mine non-existent objects to create confusing absent objects that are category-consistent but semantically inconsistent. This enhances the model’s ability to distinguish between similar objects. We guide the LLM to generate objects similar to those in the caption but with subtle differences. For example, in Fig. 5 (right image), “ Person feeding a cat ” is a confusing absent ob-ject. Rejecting it requires the model to understand that the main target is a “ Person ” and recognize that the object in the “feeding ” relationship is a “ dog ” not a “ cat ”. We also guide the LLM to generate descriptions with negative semantics (e.g., without , that is not ) to enhance understanding.

# 5. Experiments 

In this section, we first detail the implementation of ROD-MLLM (Sec. 5.1). Then, we evaluate it from multiple tasks: language-based object detection (Sec. 5.2), basic referring and grounding (Sec. 5.3), and general referring expression comprehension (Sec. 5.4). Finally, we conduct ablation ex-periments (Sec. 5.5) and give qualitative analysis (Sec. 5.6). 

5.1. Implementation Details 

Model Setting. We use CLIP ViT-L-336px [42] as the visual encoder and Vicuna-7B v1.5 [9] as the LLM. OWLv2 [38] serves as the low-level locator, with Ground-ing DINO-T [32] also tested in ablation studies (Sec. 5.5). For bounding box extraction, we use {1,2,L}-gram to iden-tify query objects from user input, where L is the length of words in the user query. Bounding boxes are filtered with NMS at a 0.6 threshold, retaining up to 100 boxes with con-fidence scores above 0.12. 

Training Setting. ROD-MLLM’s training consists of two stages: pre-training alignment and instruction fine-tuning. In the first stage, we train the image and region projectors with a learning rate of 1e-4 and a batch size of 128 for 2 epochs, keeping other parts frozen. In the second stage, we introduce the LoRA [20] module for the LLM, using the same learning rate and batch size for 1 epoch. The LoRA parameters are set to a rank of 128 and an alpha of 256. 

Datasets. We collect and unify multiple datasets into previously delineated task format, focusing on global and regional visual feature alignment pretraining. For global alignment, we use 558K image-caption pairs from LAION-CCSBU [45]. For regional alignment, we utilize COCO [27] and Objects365 [44] for single and dense de-tection training, our automatic annotated data ROD for language-based object detection. Additionally, we use Re-fCOCO/+/g [23, 36, 57], gRefCOCO [29], and sampled GRIT-20M [40] for REC, and Flickr30K Entities [41] for grounded captioning. Visual Genome [24] is used for single and dense region captioning to align region anchor tokens. During instruction-tuning stage, most of the data is sampled from pre-training data, and LLaVA Instruct 665K [30] and VCR [59] are introduced for global and regional dialogues. Please refer to the Appendix for more data details. 

5.2. Evaluation on Language-Based Detection 

Evaluation Benchmarks and Metrics. We conduct zero-shot evaluations on two language-based detection bench-marks, OmniLabel [43] and D 3 [50]. For OmniLabel, we evaluate Average Precision for descriptions (AP-d), includ-ing fine-grained metrics like AP-dP for positive descriptions and AP-dS/M/L for descriptions of varying lengths ( ≤ 3, 4 

∼ 8, > 8). For D 3, the AP metric is divided into Presence (Pres) and Absence (Abs, e.g., refrigerator without fruit )descriptions, along with a comprehensive metric (Full). 

Evaluation Results. # 6. Conclusion 

We introduce ROD-MLLM, a multimodal large language model designed for more reliable object detection using free-form language. It utilizes a query-based low-level localization method to accurately extract relevant ob-jects for high-level comprehension. To address dataset limitations, we design an automated annotation pipeline and build the ROD dataset, which includes rich object descriptions and corresponding bounding boxes in var-ious quantities.
