## 摘要
Token剪枝策略通常为单一识别流程设计，但预训练的视觉Transformer会在具有不同空间需求的任务间被复用。我们要探究剪枝策略的哪些部分能在图像分类、语义分割和目标检测之间迁移。针对每个流程，受控探针冻结无剪枝检查点，并在不重新训练的情况下，每次在一个符合条件的层上应用一系列无参数削减准则。探针揭示了三处差异：分割和检测对这些准则的排序不同；分类对最早层中基于注意力的剪枝尤其敏感；密集任务偏好相反的恢复端点。这些发现促使我们提出任务自适应剪枝（Task-Adaptive Pruning, TAP）。现有寄存器令牌充当与任务无关的特征伪影存储。TAP则改为每个任务引入一个任务寄存器令牌，并且只激活当前任务对应的那一个。其演化状态对令牌进行排序，在深度上分配精确的移除预算，并为密集特征设置恢复尺度。在最终保留率ρ=0.5时，我们联合适配的模型TAP-J在ADE20K上以1.30倍编码器吞吐量达到47.0 mIoU，在COCO上以1.32倍编码器吞吐量达到53.7 box AP，同时在ImageNet-1K上保持竞争力。

## Abstract
Token-pruning policies are usually designed for a single recognition pipeline, but pretrained Vision Transformers are reused across tasks with different spatial demands. We ask which parts of a pruning policy transfer across image classification, semantic segmentation, and object detection. For each pipeline, controlled probes freeze the no-pruning checkpoint and apply a series of parameter-free reduction criteria at one eligible layer at a time without retraining. The probes reveal three differences: segmentation and detection rank the criteria differently, classification is especially sensitive to attention-based pruning in the earliest layers, and the dense tasks prefer opposite recovery endpoints. These findings motivate Task-Adaptive Pruning (TAP). Existing register tokens serve as task-agnostic storage for feature artifacts. TAP instead introduces one task register per task and activates only the current one. Its evolving state ranks tokens, distributes an exact removal budget over depth, and sets the recovery scale for dense features. At a final keep rate of $ρ=0.5$, our jointly adapted model, TAP-J, reaches $47.0$ mIoU at $1.30\times$ encoder throughput on ADE20K and $53.7$ box AP at $1.32\times$ encoder throughput on COCO while remaining competitive on ImageNet-1K.

## 1. 论文的核心问题与整体含义

- 预训练视觉 Transformer（ViT）通常在不同任务间共享，但现有 token 剪枝策略大多为单一识别流程设计，默认“token 重要性可以跨任务迁移”。
- 本文研究剪枝策略在图像分类、语义分割、目标检测之间的可迁移性，并揭示三类差异：
  - 分割与检测对剪枝准则的排序不同（Spearman 秩相关为 −0.62）；
  - 分类对最早层中基于注意力的剪枝尤其敏感；
  - 密集任务偏好相反的恢复端点（分割偏好完整特征偏移恢复，检测偏好仅用替身特征）。
- 基于这些发现，论文提出 **任务自适应剪枝（Task-Adaptive Pruning, TAP）**，核心思想是不再使用单一剪枝规则，而是让每个任务拥有一个独立的“任务寄存器”，动态控制 token 选择、逐层预算分配和密集特征恢复尺度。

## 2. 论文提出的方法论

- **任务寄存器（Task Register）**
  - 每个任务学习一个初始寄存器向量 \( r_t^{(0)} \in \mathbb{R}^d \)，仅当前任务的寄存器进入主干网络。
  - 寄存器与 patch token、class token 一起通过 transformer block 演化，但不被剪枝。
  - 其演化状态用于后续三个决策：token 排序、预算分配、恢复缩放。

- **任务条件化的 token 选择**
  - 在剪枝层 \( l \)，利用该层已有的 query/key 投影计算寄存器到 patch 的预 softmax 分数：
    \[
    f_i^{(l)} = \sum_{h=1}^{H} \frac{(W_q^{(l,h)} \bar r_t^{(l)})^\top (W_k^{(l,h)} \bar x_i^{(l)})}{\sqrt{d_h}}
    \]
  - 按分数降序选择保留 patch，不引入额外投影参数。

- **精确预算分配**
  - 给定全局保留率 \( \rho \)，最终保留 \( K \) 个 patch，总移除预算 \( R = N_1 - K \)。
  - 通过共享线性读出 \( w, b \) 与 sigmoid 输出每一层拟移除的比例，再经取整和容量约束，确保总移除量恰为 \( R \)。
  - 最后一个剪枝层消耗剩余预算，保证输出非空且精确满足预算。

- **密集特征恢复**
  - 每个被移除 token 在键空间余弦相似度下匹配一个保留 token 作为“替身”，存储指针与偏移 \( \delta_i \)。
  - 在密集读点，根据寄存器状态输出缩放因子 \( \alpha_t^{(l)} \in (0,1) \)：
    \[
    \hat x_i = x_{\pi^*(i)}^{(L)} + \alpha_t^{(l)} \delta_i
    \]
  - 恢复特征仅送往密集任务头，不重新进入骨干，保证编码器保持稀疏。

- **训练策略**
  - 由于硬 top-k 不可微，采用 cardinality-constrained straight-through mask：对分数加 Gumbel 噪声，解单调方程得到阈值 \( \theta \)，使软掩码总数等于连续移除目标；前向用硬掩码，反向用软掩码梯度。
  - TAP-J：每个任务单独微调一个 backbone + 寄存器 + 读出 + 任务头。
  - TAP-F：冻结共享 backbone，训练任务特定寄存器、rank-8 LoRA 更新、任务头，以及共享的分配/恢复读出。
  - 参数开销：TAP-J 仅增加 \( 3d+2 = 2306 \) 个剪枝相关参数；TAP-F 增加约 1.2M 低秩参数 + 每任务一个寄存器。

## 6. 论文的主要结论与发现

- 单一 token 剪枝规则跨任务迁移不可靠：
  - 分类、分割、检测对 11 种准则排序不同，分割与检测秩相关为 −0.62。
  - 早期层注意力剪枝对分类和分割造成较大 drop，覆盖准则更稳定；检测则相反。
  - 分割倾向于恢复完整偏移，检测倾向于直接使用替身特征。
- TAP-J 在 \( \rho=0.5 \) 时：
  - ADE20K：47.0 mIoU（−0.2），编码器吞吐 1.30×；
  - COCO：53.7 box AP（−0.3）、46.4 mask AP，编码器吞吐 1.32×；
  - ImageNet-1K：83.2 top-1（−0.4），吞吐 1.26×。
- TAP-F 以冻结共享 backbone 和少量任务特有参数实现一定性能，但损失大于 TAP-J（分类 −1.0、分割 −1.4、检测 −1.5）。
- 消融表明任务寄存器、动态分配、恢复缩放三者均重要；移除任意一项会导致明显性能下降。
- 寄存器学习到任务相关分配：分割较均衡，检测前期少删后期多删；恢复尺度分割接近 1，检测接近 0。

## 7. 优点

- **受控探针设计严谨**：冻结权重、逐层单变量变化，清晰分离任务与深度对剪枝行为的影响。
- **任务寄存器作为控制器**：将原本任务无关的 register token 转变为主动的计算控制单元，参数开销极小（2.3K）。
- **精确全局预算**：无论任务或输入，最终 token 数严格满足预设，无需辅助 rate loss。
- **密集恢复边界**：恢复只在读出端进行，保持编码器稀疏，避免了重建特征重新进入 backbone 导致的计算回退。
- **可复现性强**：补充材料提供算法伪代码、合成单元测试、组件归属表、完整探针定义和效率剖析指南。
- **多任务视角**：不仅提出方法，还提供了对共享骨干中 token 价值随任务与深度变化的实证分析。

## 8. 不足与局限

- **分类性能非最佳**：TAP-J 分类 83.2 top-1 略低于 DiffRate 的 83.3，且分类不利用恢复机制，TAP 的三项设计有一项闲置。
- **TAP-F 性能下降明显**：共享 base 的 TAP-F 在各任务上都明显弱于 TAP-J，且与某些专门方法相比优势有限。
- **检测加速有限**：由于检测头未改动，完整模型吞吐仅 1.20×，编码器加速不能完全转化为端到端收益。
- **恢复是一次性近似**：偏移来自早期层，直接加到晚期端点，没有显式跨层传输映射；多个替身偏移不可直接累加。
- **固定保留率**：每个任务/运行需要预设 \( \rho \)，不支持图像自适应计算预算。
- **检测寄存器信息延迟**：在第一个全局注意力块前，寄存器无全局上下文，导致 block 3 分配和恢复尺度恒定不随图像变化。
- **任务覆盖不足**：仅测试了 3 个标准任务，未涉及深度估计、视频、语言引导等更多密集预测任务。
- **训练算力未报告**：缺少 GPU 数量、总训练时间等资源信息，难以评估训练成本。
- **受控探针的无训练性质**：探针结果来自冻结 checkpoint，可能与可学习选择器训练后的行为存在差距。
